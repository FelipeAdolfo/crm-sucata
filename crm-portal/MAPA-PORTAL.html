1. Visao Geral do Sistema

O CRM Sucata e um portal completo para gestao de negocios no setor de sucata, desenvolvido com foco em seguranca, usabilidade e inteligencia de mercado. O sistema permite que sucateiros parceiros, compradores, analistas e gestores colaborem em um ambiente seguro e auditado.

Objetivos do Sistema

  • Cadastro e gestao de oportunidades de negocio (fornecedores, sucateiros)
  • Acompanhamento por fases do funil de vendas (Lead ate Negocio Fechado)
  • Agendamento e validacao de visitas com verificacao por GPS
  • Inteligencia de mercado com dados sobre concorrentes e precos
  • Controle de acesso com aprovacao administrativa de usuarios
  • Auditoria completa de todas as acoes no sistema

Fluxo de Requisicao

  1. Usuario acessa o portal via navegador ou app PWA
  2. Frontend (React) carrega a interface e faz requisicoes REST para a API
  3. Backend (Express) recebe a requisicao, aplica middlewares de seguranca
  4. Autenticacao verifica JWT token e permissao de acesso
  5. Prisma ORM executa consultas no PostgreSQL
  6. Resposta JSON retorna ao frontend para renderizacao

Seguranca na Arquitetura

  • Helmet.js - Headers de seguranca (CSP, HSTS, X-Frame-Options)
  • Rate Limiting - Protecao contra brute force (5 tentativas de login)
  • CORS Restrito - Apenas origens autorizadas
  • Input Sanitization - Remocao de HTML perigoso
  • JWT com expiracao - Tokens de 15 minutos + refresh de 7 dias

3. Mapa de Telas

O portal possui 11 telas principais organizadas em tres categorias: publicas (sem autenticacao), protegidas (requerem login aprovado) e administrativas (apenas admin/diretor).

3.1 Telas Publicas (Sem Login)

Tela 1: Login (/login)
Formulario de autenticacao com email e senha. Exibe mensagens especificas para contas pendentes, suspensas, bloqueadas ou rejeitadas. Integrado com rate limiting de 5 tentativas.
Componentes: Login.tsx | Hook: useLogin | Service: authService.login
Tela 2: Registro (/register)
Formulario de cadastro com validacao de senha forte (12+ caracteres, maiuscula, minuscula, numero, especial). CPF formatado automaticamente. Ao concluir, status fica PENDENTE aguardando aprovacao do admin.
Componentes: Register.tsx | Hook: useRegister | Service: authService.register

3.2 Telas Protegidas (Com Login Aprovado)

Tela 3: Dashboard (/dashboard)
Painel principal com KPIs do pipeline (total de oportunidades, negocios fechados, taxa de conversao), ranking de sucateiros, ultimas visitas agendadas, alertas de mercado e tarefas pendentes. Graficos de pipeline e performance.
Componentes: Dashboard.tsx | Hooks: useDashboard, useOpportunities | Services: dashboardService
Tela 4: Oportunidades (/opportunities)
Lista completa de oportunidades com filtros por fase, tipo, regiao e responsavel. Tabela paginada com acoes de editar, excluir e visualizar detalhes. Botao para criar nova oportunidade com modal.
Componentes: Opportunities.tsx, ModalNewOpportunity.tsx | Hook: useOpportunities
Tela 5: Detalhe da Oportunidade (/opportunities/:id)
Pagina detalhada com abas: Info (dados basicos, endereco, tipo de sucata), Contatos (pessoas de contato da empresa), Visitas (historico e agendamento), Fotos (galeria com upload), Timeline (historico de atividades e mudancas de fase).
Componentes: OpportunityDetail.tsx, TabInfo.tsx, TabContacts.tsx, TabVisits.tsx, TabPhotos.tsx, TabTimeline.tsx
Tela 6: Visitas (/visits)
Calendario e lista de visitas agendadas. Filtros por status (agendada, confirmada, em andamento, concluida, cancelada). Cadastro de novas visitas com data, objetivos e checklist. Validacao por GPS no momento da visita.
Componentes: Visits.tsx | Hooks: useVisits, useCreateVisit, useUpdateVisit
Tela 7: Inteligencia de Mercado (/market-intel)
Cadastro e consulta de dados de mercado: precos da concorrencia, novos competidores, variacao de precos, mudancas de fornecedores. Filtros por tipo, regiao e periodo.
Componentes: MarketIntelligence.tsx | Service: api (direto)
Tela 8: Relatorios (/reports)
Relatorios gerenciais: pipeline de oportunidades (por fase), conversoes (por mes), desempenho de visitas, exportacao para CSV. Requer perfil Gerente ou superior.
Componentes: Reports.tsx | Service: api (direto) | Requer: MANAGER+
Tela 9: Usuarios (/users)
Lista de usuarios do sistema com filtros por perfil e status. Admin pode suspender, reativar e alterar perfis. Visualizacao de dados cadastrais.
Componentes: Users.tsx | Service: api (direto) | Requer: ADMIN
Tela 10: Configuracoes (/settings)
Perfil do usuario logado: dados pessoais, alteracao de senha (com validacao de senha forte), preferencias do sistema.
Componentes: Settings.tsx | Hook: useMe, useChangePassword

3.3 Telas de Administracao

Tela 11: Aprovacao de Usuarios (/admin/user-approval)
Painel exclusivo para ADMIN e DIRETOR. Lista usuarios com status PENDENTE. Permite aprovar (com escolha de perfil) ou rejeitar (com motivo). Notificacao automatica ao usuario aprovado.
Componentes: UserApproval.tsx | Hooks: usePendingUsers, useApproveUser, useRejectUser | Requer: ADMIN/DIRECTOR

Cada perfil herda as permissoes dos perfis abaixo dele na hierarquia. Por exemplo, um MANAGER pode fazer tudo que um ANALISTA, COMPRADOR e PARCEIRO fazem.

6. Fluxos Principais

Fluxo 1: Cadastro e Aprovacao de Usuario

Usuario acessa /register -> Preenche dados (nome, email, CPF, telefone, senha forte) -> Sistema cria usuario com status = PENDING -> Admin recebe notificacao (ou visualiza em /admin/user-approval) -> Admin analisa e aprova (escolhendo perfil) ou rejeita (com motivo) -> Se aprovado: status = ACTIVE, usuario recebe notificacao -> Usuario faz login em /login e acessa o sistema

Fluxo 2: Cadastro de Oportunidade

Usuario autenticado acessa /opportunities -> Clica em "Nova Oportunidade" -> Preenche dados basicos (nome, tipo, documento, endereco) -> Sistema cria oportunidade na fase = LEAD -> Usuario pode adicionar contatos, fotos, agendar visita -> Ao avancar fases, sistema registra na timeline

Fluxo 3: Visita com Validacao GPS

Usuario acessa /visits -> Agenda visita para oportunidade (data, objetivos, checklist) -> No dia, visitante vai ao local -> Sistema captura GPS do visitante -> Calcula distancia entre GPS do visitante e GPS cadastrado da oportunidade -> Se dentro do raio configurado: visita validada -> Visitante registra resultado e fotos

9. Camadas de Seguranca

O sistema implementa 10 camadas de seguranca para proteger dados e acesso:

CamadaImplementacaoProtecao
1. HTTPS / SSLFornecido automaticamente pelo RailwayTransmissao criptografada
2. Headers de SegurancaHelmet.js com CSP, HSTS, X-Frame, etc.Protecao contra XSS, clickjacking
3. Rate Limiting5 tentativas de login / 100 req. por 15 minProtecao contra brute force
4. CORS RestritoApenas origens configuradasProtecao contra CSRF
5. JWT + RefreshToken 15 min + refresh 7 diasAutenticacao segura com renovacao
6. Aprovacao de UsuariosStatus PENDING ate aprovacao do adminNenhum acesso nao autorizado
7. RBAC7 perfis hierarquicosAcesso baseado em perfil
8. Validacao ZodTodos os endpoints validam inputsProtecao contra dados invalidos
9. SanitizacaoRemocao de HTML perigoso dos inputsProtecao contra XSS
10. AuditoriaLog de todas as acoes com IP e timestampRastreabilidade completa
